微软携手 fal：在 Microsoft Foundry 中构建下一代多模态 AI 体验

2026年11月6日
 | Microsoft Foundry
 | 阅读

微软和 fal 最近宣布了一项合作：Kling、LTX、MiniMax 三个系列的视频模型进入 Microsoft Foundry 公共预览，以 Azure 第一方服务的形式提供，覆盖 text-to-video 和 image-to-video 两类生成方式。我把公告梳理了一遍，下面是值得关注的点。

视频生成的需求并不统一。创意团队拿到一份文字简报，想多试几种演绎；零售商要把一张定稿的产品图变成几秒钟的动态概念；做应用的开发者则想把图像生成和视频生成串成一条工作流，从描述到画面再到场景。这些场景对画质、运动控制、交付时间和成本的要求各不相同，单靠一个模型撑不起完整的愿景。这也是多模型方案逐渐成为共识的原因。

“fal 今年在生成式媒体上的采用增长非常快，覆盖广告、营销、游戏等所有行业。与微软合作，我们双方才能真正服务好整个创意生态，并确保所有依赖生成式媒体的 AI 方案走向多模型化。” —— Burkay Gur，fal 联合创始人

fal 的生成式媒体平台

fal 是面向创作者和开发者的生成式媒体全栈平台，通过 API 提供超过 1500 个模型，覆盖图像、视频、音频、3D 和生成式世界。平台同时提供推理、训练和生产环境运行所需的基础设施，还有自研的后训练（post-trained）模型，在速度和质量上做了优化。

这种专注是有道理的。生成式媒体既是创意活，也是工程活：一个吸引人的 demo 只是起点，生产环境的应用还要扛得住真实流量、随需求扩展，并在画质、延迟和成本之间找平衡。

通过这次合作，开发者可以在 Microsoft Foundry 里访问由 fal 提供服务的一批视频模型，模型本身来自各自的研发公司。初期阵容让团队能按创意需求选模型，而不是所有任务都压在同一个模型上，后续还会增加更多模型。

面向不同场景的模型阵容

初期阵容包括 Kling v3 Pro、LTX-2.5 Fast、LTX-2.5 Pro、MiniMax H3 Max 和 MiniMax H3 Max Turbo，起点各异。快速探索创意概念的团队会优先考虑速度和成本；产出少量高保真资产的团队更看重输出质量。应用是从文字还是从既有图像出发，以及画质和成本上的要求，同样影响选择。

Kling：从静态图到有导演感的镜头

Kling v3 Pro 把电影级画面和流畅运动，与原生音频生成、自定义元素支持放到了一起。它的 image-to-video 能力让开发者控制一张起始图如何变成运动场景，适合重视视觉调度和运动表现的应用。

LTX：草稿和成片各用一个模型

LTX-2.5 Fast 面向快速迭代和预览，LTX-2.5 Pro 面向高保真成片。两者都支持 text-to-video 和 image-to-video，并带同步音频。

MiniMax：另一条路线

MiniMax H3 Max 和 H3 Max Turbo 是 MiniMax H3 的后训练变体，重点优化提示词遵循、美学表现和推理性能。对开发者来说，这是多一组可以拿创意简报、质量要求和性能需求去对照评估的选项。

“用视频模型做东西时，细节很关键：输出跟提示词贴得多紧、对参考图像/视频/音频保留得多好、换个想法再试一轮有多快。Kling 给开发者对参考素材到视频生成的精细控制；LTX 用 Fast 和 Pro 两个版本兼顾快速迭代和高质量输出；H3 Max 带来 fal 的后训练和推理优化，提升质量和速度。这些模型能通过 Microsoft Foundry 使用，给了开发者更多灵活性去选适合自己应用的方案。” —— Gökay Aydoğan，fal 创意工程师

企业场景要考虑的事

把视频生成放进企业应用，选对模型只是第一步。团队还需要一个平台来评估不同选项、用符合要求的模型做构建，再和应用的其余部分一起运维。

初期模型阵容托管在美国，Microsoft Foundry 是第一个提供美国托管 Kling 3 端点的服务商。企业团队需要注意：

  • 数据驻留：对有数据驻留要求的组织，托管位置是权衡因素之一，还要逐个核对各模型文档写明的数据处理和存储条款。
  • 模型评估：团队可以评估质量、性能和成本，再把视频生成与应用所需的其他模型和能力连接起来。
  • 生产就绪：走向生产时，可以使用所选服务支持的评估、优化、治理、安全、可观测性和基础设施能力。
